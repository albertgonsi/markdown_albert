
# Exercici 5. Comparació entre XML i Markdown

## a) Quina de les dues opcions és més ràpida d'escriure i més fàcil de llegir per a un humà quan s'obre el fitxer en un editor de text pla sense cap visor?

*L'opció B (Markdown) és més ràpida d'escriure i més fàcil de llegir per a una persona. Utilitza símbols senzills, com ara els guions i les caselles de verificació, per representar les tasques. En canvi, XML necessita etiquetes d'obertura i de tancament, de manera que el codi és més llarg.*

## b) Si l'Opció B és tan simple, per quina raó un sistema informàtic o una base de dades preferiria rebre o processar la informació en format XML (Opció A) quan s'envien dades entre servidors?

*Un sistema informàtic pot preferir XML perquè les dades estan organitzades amb etiquetes i atributs que permeten identificar clarament la informació. Per exemple, l'atribut estat indica si una tasca està completada o pendent. Aquesta estructura facilita que els programes puguin interpretar i processar les dades de manera ordenada.*


# Exercici 6. Per què creus que Markdown és l'estàndard dels README.md a GitHub?

*Markdown és molt utilitzat als fitxers README.md de GitHub perquè és fàcil d'escriure i de llegir. Permet organitzar la informació amb títols, paràgrafs, llistes, enllaços i blocs de codi. A més, és un fitxer de text pla que es pot editar fàcilment i que GitHub pot mostrar amb el format corresponent. Això facilita la documentació dels projectes i permet que altres desenvolupadors entenguin com funcionen.*


# Exercici 7. Quins beneficis té trobar la documentació en un fitxer README.md ben estructurat directament a la portada del repositori en lloc d'un fitxer adjunt en PDF o un document XML?

*Un fitxer README.md ben estructurat permet consultar ràpidament la informació principal del projecte sense haver d'obrir un document separat. Amb Markdown es poden organitzar els continguts amb títols, llistes, enllaços i exemples de codi, de manera que la documentació és més fàcil de llegir. A més, el fitxer es pot editar amb un editor de text i es mostra directament a GitHub. En comparació, XML està més orientat a estructurar dades i un PDF és menys pràctic per modificar directament el text del projecte.*


# Exercici 8. Raona quin format (XML o Markdown) utilitzaries en cadascun d'aquests dos casos reals de DAM/DAW.

## Cas 1. Vols escriure els apunts d'un mòdul o la guia d'instal·lació del teu projecte perquè la llegeixin els teus companys de classe.

*Utilitzaria Markdown perquè permet escriure i organitzar els apunts de manera senzilla amb títols, paràgrafs, llistes, enllaços i blocs de codi. A més, és fàcil de llegir i modificar amb Visual Studio Code.*

## Cas 2. Vols crear un fitxer de configuració on una aplicació hagi de llegir les dades dels usuaris de forma estructurada.

*Utilitzaria XML perquè permet organitzar les dades amb etiquetes i atributs, de manera que una aplicació les pugui identificar i processar. Aquesta estructura és més adequada per representar informació que un programa ha de llegir automàticament.*
